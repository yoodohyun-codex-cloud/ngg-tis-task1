# 작업 1 현재 선별 배치 5종 GUI

[index.html](index.html)을 최신 브라우저로 열면 기준 4패드와 후보 5개를 같은 단위·색상 범위·ROI로 비교할 수 있습니다. [미리보기](preview.png)와 [실행 증거](manifest.json)를 함께 보존합니다.

## 화면 사용

- 피부·접촉 8개 부담 제한이 기본입니다. 고정 전압, 총 출력 RMS 전류 합 일치, 전력 일치, 기존 복합 부담 제한을 각각 선택할 수 있습니다. 이 조건들이 동시에 같다는 뜻은 아닙니다.
- 기본파 방향 최대 TIS(2074개 표본 방향), 고정 방향 TIS, 전체 carrier 전기장 RMS를 구분하고 XY/XZ/YZ 및 깊이를 선택합니다. 지도는 실제 native 셀 값이며 보간하지 않습니다.
- 정확한 전극 윤곽·면적·출력/GND 연결, 접촉 normal 전류밀도 RMS 지도 및 최대/P95, 피부 bulk 전류밀도 최대/P95, 접촉 전압과 전력을 표시합니다. 접촉 normal 지도는 피부 bulk 벡터 전류밀도 지도가 아닙니다.
- 목표 r≤5 mm·깊이 15–20 mm의 체적 가중 mean/P10/분포, 0–5 mm 표층 및 전체 비표적 P95·고강도 부피·전역 최대 위치를 함께 확인합니다. ROI 색상 범위에서는 큰 표층 값이 clipping되며 실제 최댓값은 별도 표시됩니다.
- 원 4패드와 기존 8·12·16패드 결과의 별도 참조 표를 보존합니다. 현재 선별된 5개는 모두 4패드·2출력·공통 GND 구성입니다.

## 선정 범위와 결과

비교 요건을 충족한 완료 조건 53개, 비기준 배치 21종에서 서로 다른 배치 5종의 완료 구동 대표를 선별했습니다. 8개 공간 평가 항목의 최대 상대 위반율, 위반율 합계, 목표 P10, 평균 순서로 정렬했습니다. 저장된 모든 조건이 같은 적격성 검사를 통과한 것은 아닙니다. [누락 조건 점검](../task1-top5-context-20261022/ranking-coverage-audit.json)은 제외된 관련 조건이 이 상위 5개의 순서를 바꾸지 않음을 기록합니다. 이는 전역 최적성의 증명이 아닙니다.

1. rounded-fullface225-xy80 / rounded-expand-f35b23a22166
2. crossalloc-source225-return225-xy80 / square_3h
3. cross17p5-arm10-xy80 / square_3h (총 접촉 면적 1000 mm², 나머지 900 mm²와 다름)
4. crossalloc-source200-return250-xy80 / square_3h
5. crossalloc-source250-return200-xy80 / square_3h

기본 부담 제한에서 1위의 목표 평균/P10은 4.053222/3.634558 V/m, 기준은 4.061849/3.645736 V/m입니다. 1위는 8개 공간 평가 항목 중 4개만 통과하며, 목표 절대 세기를 증가시킨 성공 설계가 아닙니다. 모든 후보의 전체 격자·접촉 수렴성과 실험 검증 및 채택은 보류입니다.

## 정밀도와 검증 범위

정량 표·순위·통계·공통 색상 범위는 원 Float64를 그대로 유지합니다. 지도만 저장 공간을 고려해 Float32 원 표시값에서 Float16으로 변환했습니다. 원 픽셀 오차는 |Δ|≤3.1e−8+0.0005|v_raw|이며, 진폭 배율 A를 적용한 표시에서는 |Δ_display|≤|A|×3.1e−8+0.0005|A v_raw|입니다. 화면의 절대 오차 표기는 배율 적용 전 원 픽셀 기준입니다. 색상 clipping은 수치 삭제나 새로운 계산이 아닙니다.

실제 6개 조건의 접촉 최대/P95 72개 비교 및 목표 scalar 통계 18종이 저장 원결과와 일치했습니다. 실제 데이터 Chromium에서 표시 45개 조합과 모바일 390px, JavaScript 오류·외부 요청 부재를 검증했습니다. 이는 새 PDE 계산, 전체 수렴성 검증, 활성화·인체 안전·측정기 부하 검증을 뜻하지 않습니다. PBS 계면 모델의 피부 접촉 불확실성 및 무부하 probe 예측의 제한을 유지합니다.

초기 표시 실패와 모바일 폭 실패 원자료를 별도 디렉터리에 그대로 보존했으며 덮어쓰거나 삭제하지 않았습니다. compact 생성 당시 manifest의 RSS는 self-only 관측이며 Chromium 포함 aggregate RSS를 사후 검증했다고 표시하지 않습니다. 별도 최종 검증 receipt가 생기면 해당 실행의 자원 기록으로 구분합니다.
