# 작업 1 계산 재개: 중단 원인과 다음 유한 배치

계산이 이어지지 않은 직접 원인은 **계산 담당자가 첫 유한 배치들의 종료 뒤 후속 구현·진단을 이어가지 않고 턴을 끝낸 조기 판단**이다. 당시 예산과 현재 환경은 다음 승인 범위의 작업을 계속할 수 있었다. 잔차 진단 어댑터의 구현 필요를 사용자 승인 대기나 환경 차단으로 해석해서는 안 된다.

옛 `docs/cloud-restart-20261020/checkpoint.json`은 당시 여섯 run이 종료한 사실의 기록으로 그대로 보존한다. 이것을 수정해서 새 solver가 이미 실행 중인 것처럼 표시하지 않는다. 이 메모의 관측 단계에서는 루트 계산 담당자가 새 진단 어댑터와 사전등록을 준비 중이며, 새 solver 실행 시작/완료는 새 run의 실제 controller·실행 영수증으로 따로 보고한다. 무기한 백그라운드 실행은 약속하지 않는다.

## GitHub 피드백 재확인

조회별 UTC 시각·URL·응답 hash와 문서 hash는 같은 디렉터리의 `feedback-refresh.json`에 있다. 원격 작업은 GET뿐이며 메시지·댓글·병합·원격 변경을 하지 않았다.

- 새 main은 `3b5f1861…`, 원 저장소 main은 `3feb66b4…`다. 원 PR #2/#3 head는 각각 `33f0d6ab…`/`7a6b62a9…`이며 지정 피드백·응답 문서도 이전 hash와 같다.

F004의 우선순위는 같은 4패드 후보의 접촉 가장자리/XY 민감도와 정확 참조 행렬의 수치 바닥을 먼저 분리하는 것이다. 중심/ROI의 작은 변화, 결합 격자 36개 한정 gate 통과, coarse grouped 비교는 전체 XY/가장자리·연속체 수렴을 증명하지 않는다. 기존 접촉 가장자리 cache 진단 v2는 완료했으며 첫 실패 및 percentile 정의 진단을 보존한다. 동일한 완료 진단을 다시 실행하는 대신 남은 잔차·행렬 오차 바닥 문제를 다음 질문으로 삼는다.

과거 Best1의 39 scalar 통과와 3000 Hz source/loss의 엄격한 원소별 gate 실패는 그대로 `held`다. 작은 normwise 차이를 이유로 원 판정을 완화하지 않는다. 새 진단은 이 실패를 소급 통과시키거나 새 최적점을 채택하는 작업이 아니다. 전체 XY/접촉 수렴과 실험 검증, 15–20 mm 깊이 집중 성공은 계속 미검증이다.

## 재개하는 두 조건

루트 계산 담당자의 다음 유한 계획은 다음 두 단계다. 이 문서는 계획과 관측을 기록하며 PDE를 실행하지 않는다.

1. 새 잔차 진단 producer를 종전 기본 residual `1e−9`로 실행하는 **coarse 3000 Hz 한 주파수 대조**를 먼저 등록한다. 기존 같은 물리 조건의 3000 Hz 결과에 대해 operator·전계/전위·회로/손실과 단위·소스 정규화의 회귀 gate를 확인한다. gate가 실패하면 후속 fine 진단을 시작하지 않는다.
2. 대조가 통과하면 hXY=50/120 mm의 같은 물리 모델에서 residual `1e−11`의 **3000 Hz 한 주파수 진단**을 한 조건만 수행한다. source/loss의 작은 비대각 성분과 대칭성·보존식·실제 잔차를 대조해 solver 오차 바닥과 접촉/격자 영향을 구분한다. 기존 Best1 참조 gate의 실패 이력과 원시 배열을 유지한다.

고정 D50·SC/dermis/fat/muscle 0.1/5/5/15 mm·윗면 접촉·4패드/2출력·공통 GND·High-Z 1 Vpp=0.5 Vpeak·50 Ω 및 비구동 출력 종단은 보존한다. 같은 물리 조건의 설정·마스크·접촉·주파수별 연결과 실제 새 코드 hash를 사전등록한다. 이 단일 주파수 진단 자체를 완전한 두 반송파 TIS 결과라고 부르지 않는다.

종전 `TisSweep.Net.solve`의 residual `1e−9`는 하드코딩되어 있었고 이를 바꾸는 기존 CLI flag는 없었다. 재개 준비에서는 정확한 새 어댑터·별도 등록 경로를 구현하고 회귀를 확인해야 한다. 존재하지 않는 flag를 명령에 붙이거나 동결 코드를 조용히 변경했다고 가정하지 않는다. 일반 구현과 이미 승인된 한정 진단에 새로운 사용자 승인은 필요하지 않다.

누적 예산은 **기존 ledger에서 계속 차감**하며 0으로 초기화하거나 한도를 늘리지 않는다. 원본·부분/실패·이전 결과·예약 공간도 보존한다. 새 계산을 실제로 시작할 때는 같은 전역 실행 잠금 아래 새 run ID·정확한 유한 입력·중단 조건과 source/config SHA를 고정하고 진행 시각을 기록한다.
