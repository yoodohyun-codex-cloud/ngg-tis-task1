# 유한 실행기 운영

이 실행기는 대화 응답 뒤 첫 배치만 끝나고 후속 계산이 사라지던 문제를 줄이기 위한 명시적인 유한 큐다. 무기한 상주 서비스나 예약 자동화가 아니다.

완료된 6조건 coarse run을 입력으로 받아 전체 피부 audit·순위 → 최대2조건 xy80 → 한 설계의 xy100/SC4/bulk 최대3조건 → 등록된 격자 비교 → 결과 화면 갱신 순서로 진행한다. 단일 PDE 잠금은 기존 실행자가 소유하고, 순환 실행기는 별도 중복 실행 잠금을 소유한다. 원시 결과와 실패 증거를 덮어쓰거나 삭제하지 않는다.

CPU1·동시PDE1·800000셀·600초/조건·누적6600초·heap2GiB·RSS3GiB·디스크 예약2GiB를 유지한다. 기존 예산 원장을 이어 쓰고 자식이 차감한 시간을 중복 차감하지 않는다. 다음 단계의 최대600초×조건수와 마지막120초 렌더 예약이 부족하면 원인을 남기고 멈춘다.

매 단계에서 source HEAD/코드/계획/기준·입력 hash를 확인한다. GitHub 검토 PR1의 head·댓글·리뷰를 GET으로 확인하고 변경이나 조회 실패 시 다음 계산 준비 전에 멈춘다. 새 피드백을 자동으로 채택하지 않는다. C1과 최적 후보 채택도 자동 실행하지 않는다.

실행 예:

```sh
python tools/task1_finite_loop.py --coarse-run /workspace/ngg-tis-task1/data-native/cloud-fourpad-20261020T001400Z --output /workspace/ngg-tis-task1/runtime/finite-loop-20261020T002600Z
```

`checkpoint.json`에 PID/startticks·시각·현재 자식·단계·정확한 다음 명령·완료/자원부족/오류/피드백 검토 사유를 기록한다. heartbeat 시각만으로 생존을 판단하지 말고 PID와 시작 tick 및 실행 잠금을 확인한다. 같은 output 경로로 재실행하거나 이미 계산한 조건을 새 워커에서 반복하지 않는다. 실패 시 저장된 단계·현재 자식·완료 캐시를 먼저 조사한다.

범위 안의 큐를 모두 끝내면 `completed_finite_queue`가 된다. 이 상태는 연구 목표 달성·전체 격자 수렴·실험 검증을 뜻하지 않는다. 이번 수치 결과와 새 피드백에 따른 다음 질문은 별도 사전등록과 검토를 거친다. 원시 기저는 로컬 보존이며 지속 원격 백업 여부는 별도 영수증만 따른다. 기존 COMSOL 및 측정기 실제 부하 검증의 보류 상태도 유지한다.
